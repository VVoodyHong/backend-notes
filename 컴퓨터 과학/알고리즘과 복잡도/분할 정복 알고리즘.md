# 분할 정복 알고리즘

## 핵심 정의
분할 정복(divide and conquer)은 문제를 더 작은 하위 문제로 나누고, 각 결과를 구한 뒤 합쳐 원래 문제를 해결하는 설계 방식이다. **분할(divide) → 해결(conquer) → 결합(combine)**의 비용과 종료 조건을 함께 분석한다. 재귀를 사용한다는 사실만으로 효율적인 분할 정복이 되는 것은 아니다.

대표 사례인 병합 정렬(merge sort)은 배열을 반씩 나누어 정렬한 뒤 두 정렬 결과를 병합한다. 여기서는 메모리에 들어오는 배열을 비교자로 정렬하는 순차 구현을 다룬다.

## 동작 원리 / 구조

### 반열린 구간과 종료 조건
`[lo, hi)`처럼 시작은 포함하고 끝은 제외하면 길이는 `hi - lo`다. 길이 0 또는 1에서 종료하고 `mid = lo + (hi - lo) / 2`를 기준으로 `[lo, mid)`, `[mid, hi)`로 나누면 누락·중복 없이 더 작은 구간을 얻는다.

다음 코드는 원본 배열을 제자리에서 갱신하지만 보조 배열 O(n)을 쓰므로 공간복잡도 의미의 in-place 정렬은 아니다. 입력 배열과 비교자는 null이 아니며, 비교자는 일관된 순서를 정의한다고 가정한다.

```java
static <T> void mergeSort(T[] a, java.util.Comparator<? super T> order) {
    T[] work = a.clone(); // 전체 정렬에서 한 번만 확보
    sortRange(a, work, 0, a.length, order);
}

static <T> void sortRange(T[] a, T[] work, int lo, int hi,
                         java.util.Comparator<? super T> order) {
    if (hi - lo <= 1) return;
    int mid = lo + (hi - lo) / 2;
    sortRange(a, work, lo, mid, order);
    sortRange(a, work, mid, hi, order);
    System.arraycopy(a, lo, work, lo, hi - lo);
    int left = lo, right = mid;
    for (int out = lo; out < hi; out++) {
        if (left == mid) a[out] = work[right++];
        else if (right == hi) a[out] = work[left++];
        else if (order.compare(work[left], work[right]) <= 0)
            a[out] = work[left++]; // 동률이면 왼쪽: 안정성 유지
        else a[out] = work[right++];
    }
}
```

### 비용을 재귀식으로 분리하기
균등하게 반씩 나누는 병합 정렬은 `T(n) = 2T(n/2) + Θ(n)`으로 설명할 수 있다. 각 깊이의 병합량이 Θ(n), 깊이가 Θ(log n)이므로 전체 시간은 Θ(n log n)이다. 홀수 길이의 바닥·천장 분할도 같은 점근적 결론을 갖는다. 위 구현의 최대 보조 공간은 배열 O(n)과 호출 스택 O(log n)을 합친 O(n)이다.

퀵 정렬(quick sort)은 결합이 거의 없지만 분할 균형이 입력과 피벗 선택에 좌우된다. 매번 0개와 n-1개로 나뉘면 깊이 O(n), 시간 O(n²)이 된다. 따라서 재귀 호출이 두 번이라는 사실만으로 O(n log n)을 보장할 수 없다.

## 실무 관점
- 이미 있는 정렬 라이브러리를 우선 사용한다. 직접 구현은 경계·안정성·비교자 비용을 이해하거나 특수 데이터 흐름을 설계할 때 의미가 있다.
- 매 재귀마다 부분 배열을 복사하면 총 할당량이 커진다. 구간 인덱스와 재사용 보조 배열로 최대 생존 메모리와 누적 할당량을 구분해 관리한다.
- 독립 하위 문제는 병렬화 후보지만 태스크 생성·결합·메모리 대역폭에도 비용이 든다. 작은 구간은 순차 처리하고 임계값을 측정한다. 공유 보조 배열을 쓰는 병렬 구현은 동시에 접근하는 범위가 겹치지 않아야 한다.
- 비균등 분할이나 사용자 입력으로 깊이가 증가하는 재귀는 스택 고갈을 확인한다. 반복문·명시적 스택으로 바꾸어도 알고리즘 자체의 O(n²) 시간 문제가 자동 해결되지는 않는다.

## 심화 Q&A

### Q. 분할 정복과 동적 프로그래밍은 언제 구분하는가?
A. 병합 정렬의 두 구간은 서로 다른 원소를 정렬하므로 같은 구간 결과를 반복 계산하지 않는다. 반면 순진한 재귀 피보나치는 같은 부분 문제가 반복된다. 겹치는 부분 문제의 결과를 저장해 재사용하는 메모이제이션·동적 프로그래밍이 이 중복을 줄인다. 문제를 잘게 나누는 것과 중복 계산을 제거하는 것은 별도 판단이다.

### Q. 동률에서 오른쪽을 먼저 선택하면 무엇이 달라지는가?
A. 키 순서는 여전히 정렬되지만 원래 앞에 있던 동률 원소가 뒤로 밀릴 수 있어 안정성(stability)이 깨진다. 위 구현은 분할 전 왼쪽 구간의 원소가 먼저 있었으므로 동률에서 왼쪽을 선택하고, 각 재귀 결과도 안정적이라는 귀납적 조건으로 전체 안정성을 유지한다.

### Q. 보조 배열을 한 번만 만들면 왜 메모리가 O(n log n)이 아닌가?
A. 모든 호출이 하나의 길이 n 배열을 구간별로 재사용한다. 순차 실행에서 동시에 남아 있는 호출 프레임은 재귀 깊이만큼이므로 O(log n)이다. 재귀 트리 전체의 호출 수와 동시에 살아 있는 메모리는 다르다. 매 호출마다 배열을 만들어도 총 할당량과 최대 생존량을 별도로 분석해야 한다.

### Q. 하위 문제를 모두 병렬 실행하면 코어 수만큼 빨라지는가?
A. 결합이 순차라면 그 구간은 그대로 남는다. 위 병합 방식은 마지막에 전체 n개를 순차 병합하므로 무한한 실행 자원이 있어도 그 작업보다 빠르게 끝날 수 없다. 병렬화 가능 비율과 스케줄링·메모리 대역폭을 함께 평가한다. Java의 작업 분할·합류는 [[Fork-Join 프레임워크]]와 연결된다.
